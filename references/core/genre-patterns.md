# ジャンル別・直感的メカニクス実装パターン集（Genre Intuitive Patterns）

経路C（ジャンルが確定していて具体的な実装が要る時）に読む。

**使い方**: パターンをそのまま提案しない。「なぜこのジャンルでこれが効くのか」を SKILL.md の問い1〜5 のどれに当たるかで示し、対象タイトルの目標感情に照らして採否を判断すること。ここにあるのは**選択肢のカタログであって、正解のリストではない**。

## 1. リズム・音楽ゲーム

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **操作空間** | ボタンは1〜2個。増やすならレーン（空間）で分ける。長押し・フリックはモーダルスイッチとして既存入力に第2の意味を持たせる | 問い3（同時新規要素4以下）／問い4（密結合） |
| **予測可視化** | 判定ラインの1〜2小節前からノーツと軌跡を提示。スクロール速度はプレイヤーに開放 | 問い5 Pre。反応時間の物理的制約 |
| **演出配置** | 判定エリア（Micro）は徹底的に簡素、派手演出（Macro）は周縁へ | 空間分離ルール。中心視野の占有を避ける |
| **入力の音化** | 入力ごとに楽曲のステムを割り当て、量子化して発音。ミスは不協和音ではなく「音の欠落」で伝える | 3感統合。罰より欠落のほうが再挑戦につながる |
| **キャリブレーション** | 初回プレイ**後**に導線を置く。自動推定を第一候補に | ズレを体験する前に基準は持てない |

数値は `core/rhythm-and-synesthesia.md` 2章。

## 2. 身体運動・エクササイズ（Exergame）

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **認識の閾値** | 曖昧な入力は「弱い成功」として拾う。取りこぼしのコストは誤検出よりはるかに高い | 運動の曖昧さの許容 |
| **アバテアリング** | 不格好な動きをアバター側で優雅な大技に補正して返す | 万能感。人前でのプレイの恥ずかしさ対策も兼ねる |
| **ドリフト防止** | **視界内**に境界表示（足元は見ていない）。前進動作と後退動作を交互に要求。自動リセンター | UFD。怪我につながる唯一の失敗モード |
| **疲労設計** | 高強度は30〜90秒、間に回復区間。疲労ピークを曲のクライマックスに合わせる | 二因子感情理論（覚醒への感情ラベリング） |
| **Pre の延長** | 全身動作の予告は500ms〜1秒前。判定窓も指の操作より広く | キネステティック・ラグ |

## 3. アクション／プラットフォーマー

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **ジャンプ** | 押し込み時間で高さが変わる（連続的I/O）。自機の真下に接地影を出す | ナチュラルマッピング／着地点予測のシグニファイア |
| **入力の寛容化** | コヨーテタイム約100ms、入力バッファ約100〜150ms | 「押したのに反応しない」の正体はほぼこれ。**プレイヤーは自分の入力が遅れたことを自覚していない** |
| **HUD排除** | HPバーの代わりに画面周縁の赤化と心音。残弾は武器モデル自体で表現 | 一貫性の原則。情報を世界側に埋める |
| **敵の予備動作** | 攻撃の前に必ず可読なモーション。速い攻撃ほど予備動作は長く | 問い5 Pre。回避不能な攻撃は難易度ではなく理不尽 |
| **ヒットストップ** | 命中の瞬間に数フレーム停止＋振動 | 問い5 Immediate。手応えの実体はほぼこれ |
| **通れる／通れない** | 通れる床と通れない壁を、色や質感で一貫して区別。例外を作らない | 偽アフォーダンスの排除。一度裏切ると全ての床が疑われる |

## 4. パズル／ハイパーカジュアル

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **密結合** | 「サイズ」が同時に「重量」「攻撃力」「被発見率」を決める | 問い4。ルール1つで判断が3次元になる |
| **ポカヨケ** | 合わないピースは物理的にハマらず弾き返される。禁じ手をルールで書かず構造で潰す | 覚える負荷がゼロになる |
| **初手の誘導** | 最初の1手だけが可能な盤面から始める。説明せずに操作方法を教えられる | 問い1。チュートリアルをレベルデザインで置き換える定石 |
| **失敗の可読性** | 失敗直後に「何が原因か」を見せる。ペナルティを軽くするより効果が大きい | 良い失敗の条件＝原因の特定可能性 |
| **1ルール1ステージ** | 新ルールを導入したステージでは、他の難しさを足さない | セグメンティング |

## 5. VR／空間コンピューティング

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **手先操作** | ドアノブを掴んで回す、レバーを倒すを1対1で再現 | Real Affordance ＋ ナチュラルマッピング。抽象化するほど説明が要る |
| **触覚補強** | 接触の瞬間に振動、押し込めない限界で手が離れる（ロックアウト） | 3感統合。VRで最も欠落しがちな層 |
| **偽アフォーダンス厳禁** | 掴めそうな物は掴めるようにする。無理なら**掴めそうな形にしない** | VRでは手を伸ばすコストが高く、裏切りの心理的コストも高い |
| **視野内の安全** | ガーディアン境界は足元でなく視界内に。移動酔い対策はデフォルトON | UFD／VR酔いは離脱の主因 |
| **身体スケール** | UIはメートル単位で身体基準に配置。画面基準のHUDは持ち込まない | 空間側にマッピングし直す |

## 6. ストラテジー／シミュレーション

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **情報の段階開示** | 初期盤面は選択肢を3つに制限し、勝利条件を1つだけ提示 | 問い3。ストラテジーの離脱は難しさではなく**選択肢の多さ**で起きる |
| **因果の可視化** | 数値変動の理由をホバー等で常に辿れるようにする | 情報過多と情報飢餓の間。理由が辿れれば数値は多くてよい |
| **Undo の設計** | 探索的操作は取り消せるようにする。試行錯誤が学習経路になる | 誤操作の恐怖が探索を止める |
| **アロセントリック回避** | ミニマップは可能なら回転追従（エゴセントリック）。固定北向きはメンタルローテーションの負荷を生む | Shepard & Metzler。ただし俯瞰型戦略では固定のほうが有利な場合もあり、**ジャンルで判断が割れる数少ない項目** |

## 7. マルチプレイヤー／協力プレイ

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **他人が教師になる** | 初心者が上級者の操作を見て学べるよう、操作と結果の対応を画面上で可読に | 説明書の代替として最も強力。観察学習 |
| **反転マッピング厳禁** | 「自分に見えない情報を他人に見せる」等の反転は、説明なしでは成立しない | 実験では推測成功率0%（`core/case-studies-and-metrics.md` 1.2） |
| **役割の非対称は形で示す** | 役割が違うなら、見た目・操作数・画面レイアウトを明確に変える | 同じ見た目で違う役割は、最も混乱する構成 |
| **待ち時間の設計** | 他人のターンを待つ間にできることを置く | 情報飢餓ではなく手持ち無沙汰が離脱を生む |

## 8. 展示・インスタレーション（初見一発勝負）

説明係が常駐できない前提で、通りすがりの人が触る場合。ゲームより制約が厳しい。

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **アトラクトモード** | 誰も触っていない時、操作のデモを無限ループさせる | 最強の非言語チュートリアル。**人は説明を読まないが、他人の操作は見る** |
| **触れる範囲の物理的限定** | 触ってほしくない場所には物理的に手が届かないようにする | ポカヨケ。注意書きは読まれない |
| **10秒でリセット** | 無操作が続いたら自動で初期状態へ。前の人の状態が残ると次の人が触れない | 初見が常に同じ状態から始まることを保証する |
| **1操作で何かが起きる** | 最初の1タッチ・1歩で必ず目に見える反応を返す | 問い1。反応がなければ人は3秒で去る |
| **列と滞在時間** | 1人あたりの体験時間を設計変数として明示する（回転率） | 体験の質は待ち時間で相殺される |

## 9. 奥行き方向に迫ってくる（Z軸アプローチ）

トンネル・一人称視点・画面奥から手前へ飛んでくる構成。**横に流れるものを避けるゲームとは、認知の難しさが根本的に違います。**

### なぜ難しいのか

奥から等速で近づく物体は、画面上でほとんど動きません。見かけの大きさは距離に反比例して増えるので、**残り距離の最後の2〜3割で、見かけの変化のほとんどが起きます**。物理的には等速なのに、認知的には「急に来る」。

**つまり、難易度をプレイヤーが読めないのは難易度設計の失敗ではなく、投影の性質です。** 手当をしない限り、速度を上げた分がそのまま理不尽になります。

| 要素 | パターン | 根拠 |
| :--- | :--- | :--- |
| **Z を横の動きに変換する** | 影を落とす、床のグリッドを流す、トンネルの縞を速度と同期させる。**奥行きを、画面上で動く量に翻訳する** | 問い5 Pre。距離そのものは見えないが、動く量は見える |
| **判定は時間で定義する** | 「残り 0.3m」ではなく「残り 33ms」。距離で書くと、速度が上がった時に判定窓が勝手に縮む | 速度28m/sでは0.3mは11ms。距離ベースの判定は速度と難易度を結合させてしまう |
| **音で距離を渡す** | 近づくほどピッチ・音量・パンを変える。視覚が使えない最後の一瞬に効く | 視覚チャンネルが飽和する帯域を音で補う |
| **予告は到達の 800ms〜1.2秒前** | 見かけの変化が始まる前に、別の手段（マーカー、音、色）で予告する | Pre層。見かけの拡大に頼ると、予告と本体が同時になる |
| **非対称な当たり判定** | 取りたいものは判定を広く、避けたいものは狭く | 奥行きの誤差は横の誤差より大きい。同じ半径では取れなさすぎる |
| **危険物は判定より見た目を大きく** | 実際には当たっていないのに「かすった」と感じる。ニアミス演出の実体はこれ | ニアミスは次の一回の起動装置。判定を狭くするだけでは体験にならない |

**当たり判定と見た目の乖離は、表示半径の2〜3倍までに留める。** それを超えると「当たっていないのに取れた」が見えてしまい、逆に取れなかった時に理不尽さが跳ね返ります。

### 生成側

奥行き方向の生成では、**同時に画面へ入るオブジェクトの数ではなく、判定面に到達する時刻の間隔**を制約にしてください。距離で等間隔に置くと、速度が変わった瞬間に到達間隔が詰まり、人間の反応時間を下回ります。到達時刻を**先に決めてから**、そこへ逆算して配置する順序が安全です（`../simple/procedural-generation.md`）。

## 10. ジャンル共通の「初手」パターン

ジャンルを問わず、**最初の30秒で操作を教える**ための定石。どれもテキストを使わない。

1. **1つだけ動かす**: 静止した画面の中で1つだけが動いていると、視線と最初の操作はそこへ向かう。
2. **できることを1つに絞る**: 最初の場面では、正しい操作以外を物理的に不可能にする（ロックアウト）。失敗しようがない状況で成功体験を作る。
3. **他人にやらせる**: NPC・アバター・アトラクトモードが先にやってみせる。観察学習は説明文より速い。
4. **失敗を安全にする**: 最初の失敗にコストを置かない。試せる状況が探索を生む。
5. **必要になった瞬間に教える**: 崖の手前でジャンプを、敵が来た瞬間に攻撃を。事前の羅列は覚えられない（Just-in-Time）。
6. **身体で覚えさせる**: 説明を読ませるより3回やらせる。手続き記憶はワーキングメモリを使わない。
