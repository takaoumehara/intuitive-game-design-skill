# リズム・共感覚・身体運動の設計（Rhythm, Synesthesia & Movement）

音・光・振動・身体が絡む設計で読む。この領域が他と違うのは、**プレイヤーの身体には物理的な遅延があり、それを設計で先回りしない限り「操作が下手」ではなく「ゲームが不正確」と感じられる**点にある。

## 1. 共感覚設計（水口哲也の系譜）

### 1.1 三位一体の感覚統合（Trimodal Sensory Integration）
プレイヤーの入力（Action）に対し、視覚（Visual）・音響（Audio）・触覚（Haptics / Vibrotactile）が**同一のインパルスとして同時に知覚される**状態を作る。

3つが揃った時、プレイヤーはそれを「操作した」ではなく「**触れた**」と感じる。実体感はこの同時性から生まれる。触覚が使えない環境（キーボード、タッチ）では、**低音**が触覚の代替として機能する。腹に来る帯域は身体感覚として処理される。

### 1.2 クオンタイズ（音響量子化 / Audio Quantization）
プレイヤーの入力タイミングが一定の許容誤差（**±50ms〜100ms**）内にある場合、システム側で発音タイミングを直近の1/16拍（スナップグリッド）へ微補正する。

**目的**: 入力が不完全でも、出力される音楽は常にコード進行とグルーヴを維持する。「自分が音楽を奏でている」という万能感（Empowerment）を、演奏技能なしに成立させる。

**この領域で最も費用対効果が高い技法。** 判定は厳密に取りつつ、音は常に気持ちよく鳴る──判定の正確さと音楽的快感を分離できる。

### 1.3 サウンドステムの段階的構築（Sound Stem Progression）
各入力に楽曲のパート（ステム）を割り当てるだけでなく、**成功体験やコンボ（Multiplier）の上昇に伴って BGM のステムを動的にレイヤー追加する**（Dynamic Layering）。

```
リズムトラック → ベースライン → コード進行 → メロディ／ヴォーカル
```

失敗時は不協和音で罰するのではなく、**在るはずの音が鳴らない／レイヤーが剥がれる**という欠落で伝える。罰ではなく物足りなさとして届くため、再挑戦につながる。

### 1.4 空間分離ルール（Spatial Isolation Rule）
判定エリアと演出エリアを空間的に分ける。**視覚刺激の爆発と高いゲーム性を両立させる**唯一の方法であり、認知負荷理論における外発的負荷の抑制そのもの。

| | **マイクロ領域**（判定ライン周辺） | **マクロ領域**（周縁・背景） |
| :--- | :--- | :--- |
| 内容 | 幾何学的でシンプルなシグニファイアのみ。視覚的ノイズを極小化 | 派手な粒子、背景グラフィック、共感覚演出。周辺視野または判定完了直後の軌跡上に展開 |
| 目的 | 正確な情報伝達 | 感情の増幅 |
| 変化の速度 | ノーツ単位（速い） | フレーズ・セクション単位（遅い） |
| 派手さ | 最小限 | 上限なし |
| 失敗時 | 何が外れたかを明示 | 静かになる（罰ではなく減衰） |

この分離を破ると、**プレイヤーは上手くなるほど演出を無視するようになり、演出コストが無駄になる。** さらに、判定領域に派手な演出を出すと次のノーツが見えなくなり、意図しない形で難易度が上がる。

## 2. 3層フィードバックと判定・遅延の数値

### 2.1 3段階フィードバックループ

| 層 | タイミング | 実装 | 目的 | 欠落時にプレイヤーが言う言葉 |
| :--- | :--- | :--- | :--- | :--- |
| **Pre（事前）** | ターゲット到達の**最小2拍前（800ms〜1200ms）** | アプローチ線、拡大縮小リング、ノーツの接近、敵の予備動作 | 脳内での運動計画（Motor Planning）と予期的タイミング取り（Kinesthetic Anticipation） | 「理不尽」「見えなかった」「反応できない」 |
| **Immediate（即時）** | 入力後**100ms以内** | 効果音（Sound Stem の発音）、フラッシュ、バイブレーション | 入力が結果に結びついた実感 | 「反応しない」「重い」「押した気がしない」 |
| **Post（事後）** | 入力後 100〜500ms | 判定評価（Perfect / Great / Miss）、スコア、コンボ | 上達の可視化 | 「手応えがない」「上手くなってる気がしない」 |

**Post の配置**: 判定領域の中心を妨げない位置（視線移動が最小限で済む上下左右の縁）にポップアップする。中心に出すと次の Pre を潰す。

**Immediate は判定の成否と切り離す**のが要点。外した時も「押したこと自体」への反応は返す。無反応は、プレイヤーに「自分が下手」ではなく「機械が壊れている」と解釈されるため。

### 2.2 判定ウィンドウの多層設計

入力デバイスが指か身体かで、要求できる精度が根本的に変わる。**同じ ±40ms を全身動作に要求するのは物理的に不可能な要求**であり、プレイヤーは自分の身体を責めることになる。

| 層 | 判定窓 | 用途 |
| :--- | :--- | :--- |
| **Just / Perfect** | **±30ms 〜 ±45ms** | 厳密な音楽的一致 |
| **Good / Great** | **±70ms 〜 ±100ms** | ゲーム進行の維持。初心者が成功体験を得る帯。ここを削ると離脱が跳ねる |
| **Movement Buffer**（VR・身体運動用） | **±150ms 〜 ±200ms** | 身体慣性遅延の許容。全身動作ではこの層を基準にする |
| MISS 境界 | ±120〜150ms（指）／それ以上（身体） | これを超えると本人も「外した」と自覚している |

**カメラで顔や身体を読む入力は、Movement Buffer の側です。** 身体慣性に加えて、カメラの周期・推定・フィルタで **80〜150ms** の遅延が入力側に乗るため、Perfect 帯（±30〜45ms）を要求すると、判定は技術ではなく運を測ることになります（`camera-input.md` §4）。

### 2.3 遅延補正（キャリブレーション）
Bluetooth イヤホンや液晶テレビなどのデジタル出力デバイスは **50ms〜200ms** のレイテンシを持つ。**プレイヤーは自分の環境が遅れていることに気づかず、ゲームが下手だと感じる。** キャリブレーション機能は標準搭載する。

* 起動時ではなく、初回プレイ**後**に「ズレを感じましたか？」と聞く導線を置く。初回起動時の調整は、ズレを体験する前なので基準が持てない。
* 自動キャリブレーション（入力の平均偏差から補正値を推定）は、明示的な調整画面より成功率が高い。

### 2.4 音ズレの非対称性
* 音が**遅れる**方向：約 **100ms** から気づかれやすい（現実では音は遅れて届くため、脳が許容しやすい）
* 音が**先行する**方向：約 **45ms** から気づかれやすい（**遅れの半分以下**。現実にありえない順序のため脳が拒否する）

実務上の指針として、**演出を音より先に出す設計は、後に出す設計より危険**。

## 3. リズムゲームの鉄則

### 3.1 操作の極小化（Simplicity of Controls）
リズムキープそのものがワーキングメモリを占有する。**タイミングを取ることに認知資源を使っている最中に、選択肢を増やしてはいけない。**

* ボタン数は 1〜2 個を基本とし、増やすならレーン（空間）で分ける。空間的な分離は認知的な分離より安い。
* 長押し・フリックは**モーダルスイッチ**として使う。新しいボタンを増やすより、既存の入力に第2の意味を持たせる（密結合）。
* 譜面が難しいことと、操作が複雑なことは別物。難易度は**譜面の密度**で上げ、**操作の種類**では上げない。

### 3.2 予測可視化（Look-ahead）
人間は音を聞いてから反応するのでは間に合わない。§2.1 の Pre（最小2拍前）を空間的に保証する。

* 2拍という基準は時間に直すと BPM に依存する（BPM 120 で 1000ms、BPM 150 で 800ms）。**高速曲では時間ではなく拍数・小節数で確保する。**
* スクロール速度の調整をプレイヤーに開放する。これは設定項目ではなく、**プレイヤーごとに異なる知覚特性への対応**であり、上級者ほど必須になる。
* ノーツの軌跡・アプローチ線は、到達時刻を線形に表現する。加速する動きは到達時刻の予測を狂わせる。

## 4. 身体運動ゲーム（Exergame）の7大設計指針

Isbister & Mueller (2015) による運動ベースゲームの設計指針。

| # | 指針 | 英語名 | 実装・デザイン原則 |
| :-- | :--- | :--- | :--- |
| **1** | 運動の曖昧さを許容する | Embrace Ambiguity | 厳密なトラッキングではなく、運動の「意図」や「勢い」を評価する。センサーは身体を正確には読めず、**正確に読もうとするほどプレイヤーは認識されないことに苛立つ**。取りこぼしのコストは誤検出のコストよりはるかに高い |
| **2** | 運動表現の祝福 | Celebrate Articulation | 成功/失敗を判定するだけでなく、プレイヤーが見せた大きな動き・アクロバティックな動作を視覚・音響で派手に称える |
| **3** | 運動の認知負荷の管理 | Manage Cognitive Load | 複雑な頭脳プレイ（高度な戦術計算）と激しい全身運動を同時に要求しない。身体運動中はルールを極限までシンプル化する |
| **4** | 身体へのフォーカス | Focus on the Body | 画面上の数値やメーターではなく、心拍・呼吸・手足の伸びといった自己の身体感覚に意識を向ける演出を行う。運動ゲームの報酬は、スコアより**身体感覚の変化**にある |
| **5** | 意図的な疲労設計 | Intend Fatigue | 疲労を「予期せぬ失敗」ではなく「称賛されるべき努力・ゲームプレイの山場」として設計する。高負荷エリアの直後にはクールダウン区間を配置する |
| **6** | 身体的リスクの利用 | Exploit Risk | 安全性を担保した上で、バランスを崩しそうな感覚やジャンプの浮遊感など、ポジティブな身体的スリルを活用する |
| **7** | 想像力豊かなアバテアリング | Imaginative Avateering | プレイヤーの現実の不格好な動き（Inelegant Movement）を、画面上のアバターでは優雅で強力な大技に補正して描画する |

### 4.1 実務で足す1項目：リズムの強調
上記7指針とは別に、本スキルが実務上必ず加えるもの。**身体は等間隔の運動を得意とする。拍に乗せると、同じ運動量でも疲労の主観値が下がる。** 不規則な運動要求は疲労を増幅する。

### 4.2 疲労設計の具体値
* 高強度は **30〜90秒**を上限とし、間に低強度の回復区間を置く（インターバル構造）。
* 疲労のピークを**曲のクライマックス**に合わせると、身体的苦痛が達成感としてラベリングされる（二因子感情理論の応用）。
* 疲労から意識を逸らす最も強い手段は、テンポの速い音楽と明確な目標。筋肉ではなく画面に注意を向けさせる。

### 4.3 観客の存在
運動ゲームは人前でプレイされることが多く、**恥ずかしさが最大の離脱要因**になる。指針7（Avateering）は、この意味でも機能する──見た目が格好よければ人前で踊れる。初期段階で要求する動作は、**やっていて恥ずかしくない小さな動き**から始める。

## 5. 身体入力特有の物理制約と失敗モード

### 5.1 キネステティック・ラグ（身体慣性遅延）
アナログボタンの押し込み（数ミリ秒）と異なり、腕を振る・膝を曲げる・ジャンプするといった全身運動には **300ms〜800ms** の身体的慣性（Physical Inertia）が発生する。

**対策（WAVE方式・事前視覚化）**: 次に要求されるポーズや身体軌跡を、ゴーストアバター／空間の力のラインとして **数秒前（Look-Ahead Vector）** に空間描画する。

判定窓も §2.2 の **Movement Buffer（±150〜200ms）** を基準にする。指の操作と同じ精度を要求してはいけない。

### 5.2 意図しない前進ドリフト（Unintended Forward Drift / UFD）
VR HMD 装着時や激しい運動時、プレイヤーは自覚なく前進・横ずれし、プレイエリア外（壁や家具）に衝突する危険がある。**長時間プレイほど深刻化し、怪我につながる唯一の失敗モード。**

**ポカヨケ（強制機能）的解決策**:
* **交互設計**: 左右・上下の交互ステップを要求するノーツ配置にして、前後運動の自走を抑制する
* **セーフグラウンドリング（Safe Ground Ring）**: 足元に常に視覚的ホームリングを可視化し、**離れると背景の彩度が落ちる**視覚フィードバックを提供する。彩度の変化は、注視していなくても周辺視野で気づける
* **自動リセンター**: 一定以上のずれを検出したら、ゲーム側の基準座標を静かに更新する。プレイヤーに「戻ってください」と言わない

### 5.3 疲労による判定の意味変化
プレイ後半、同じ判定窓が実質的に厳しくなる（身体の精度が落ちるため）。**後半で難易度を上げると、体感の難易度は二重に上がる。** 譜面の難易度カーブは、疲労カーブを引いた後で設計する。

## 6. 触覚フィードバック（Vibrotactile Feedback）の統合パターン

### 6.1 衝撃の粒度（Haptic Frequency Mapping）
音の帯域と振動の質を対応させると、触覚が「音の一部」として知覚される。

| 対象 | 振動 |
| :--- | :--- |
| 高音 / 軽いノーツ | **高周波・弱振動**（短発の Tick） |
| 重低音 / 大きいノーツ | **低周波・重振動**（残響のある Rumble） |

### 6.2 空間定位ハプティクス（Spatial Haptics）
左からアプローチするノーツは**左コントローラー／左グローブのみ**を振動させる。視覚情報に頼らない空間知覚を支援でき、視線が判定領域に固定されていても方向が分かる。

### 6.3 VR での接触表現
物体に触れた瞬間に振動、押し込めない限界で手が離れる（ロックアウト）。VR で最も欠落しがちな層であり、偽アフォーダンスの温床でもある。

## 出典の扱い

数値は業界の実務値と知覚研究の観測を混ぜて整理している。§4 の7指針は Isbister & Mueller (2015) に基づくが、対外資料へ引用する際は原典の文言を確認すること。§2 の判定窓・遅延値はタイトル固有のチューニング値であり、普遍的な法則ではない。出発点として使い、実機で調整する前提で扱う。
