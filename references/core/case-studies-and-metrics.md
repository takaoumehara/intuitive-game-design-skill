## 1. 説明書なしプレイテストの観測事例

「初見の人は何を勝手に推測するか」の実データ。**設計者の意図は、これらの前では無力**である点が共通の教訓。

### 1.1 Hive Pocket — 既存スキーマによる乗っ取り
* **条件**: 説明書を排除し、六角形タイルのみを提示。教員・スタッフ層（平均32〜40歳）と大学生層（平均19〜22歳）に実施。
* **観測**: 教員層は「六角形＝ハニカム構造＝女王蜂を囲む」と論理的に正解へ到達。大学生層は「白と黒のコマ＝チェス（白が先手）」という既存スキーマに引きずられ、正解から遠ざかった。
* **教訓**: **同じ物体が、集団によって別のスキーマを起動する。** 「直感的」は集団依存であり、テストの被験者属性を記録しない限り結果は読めない。

### 1.2 Hanabi — 反転マッピングの敗北
* **観測**: 「手札を自分に見せず、他人に見せる」という反転マッピングを、説明書なしで推測できた被験者は**0%**だった。「カードは自分が見て隠すもの」というスキーマが強固すぎるため。
* **シグニファイア誤認**: 青い時計トークンを、大学生の多数が「タイマー（時間制限）」と誤認した。設計意図は「他人にヒントを出せるリソース」。
* **教訓**: **既存スキーマに逆らう中核ルールは、シグニファイアでは救えない。** 説明を前提にするか、ルールを変えるかの二択になる。時計＝時間という連想は、色や配置では上書きできない。

### 1.3 Goblin Dice — 属性による解釈の分岐
* **条件**: 被験者80名（男性50／女性30）。「石の球体（ボルダー）」の意味を推測させた。
* **観測**: 男性群は「押しつぶしに来る敵（生存ゲーム）」、女性群は「協力して運ぶボール（チームスポーツ）」と解釈した。
* **教訓**: 中立的な形状は、集団ごとに正反対の意味を持ちうる。**意図を1つに絞りたいなら、形状に感情を付与する**（トゲ、怒り顔、傷跡）。中立＝万人向けではなく、中立＝解釈が割れる。

### 1.4 D&D 変則ダイス — 公平性の知覚とフォント視認性
* **公平性**: システム未経験者の**62%**が不規則な形状のダイスを「イカサマ・偏りがある」と疑った。経験者では**70%**が公平と認識。
* **視認性**: コントラストの低い装飾ダイスは読み取りエラーを多発させ、強いフラストレーションから離脱（churn）を招いた。
* **教訓**: **見た目の美しさが機能を侵食すると、美しさごと嫌われる。** また、公平性は確率ではなく知覚の問題として扱う必要がある。

### 1.5 共通して観測されるもの：アポフェニアによるルール創作
被験者は、情報が足りない時に**存在しないルールを発明して埋める**。Hive Pocket ではタイル裏面の空白を見た被験者が「裏返して伏せてドローする隠匿ゲーム」という架空のルールを構築した。

**教訓**: 空白・未使用領域・意味のない差異は、プレイヤーによって意味を与えられる。**説明していないものは「無」ではなく「誤解の余地」**として存在する。

## 2. 認知・知覚の数値

| 項目 | 数値 | 出典・性質 |
| :--- | :--- | :--- |
| ワーキングメモリ容量 | **4±1 チャンク** | Cowan (2001)。査読研究。実務の基準はこちら |
| （参考）マジカルナンバー | 7±2 | Miller (1956)。広く引用されるが現代では過大評価とされる |
| メンタルローテーションの反応時間 | **回転角度に比例して直線的に増大** | Shepard & Metzler (1971)。査読研究 |
| 「即座」と感じる上限 | **約100ms** | 知覚処理のサイクル。HCI で広く使われる基準 |
| 「流れが途切れない」上限 | **約400ms** | Doherty threshold。応答時間と生産性の研究由来 |
| 「待たされた」と感じ始める | **約1秒** | 思考の連続性が切れる境界として扱われる |

### 2.1 認知的・身体的許容パラメーター（Quantitative Thresholds）

**時間・フィードバック閾値**
* **即時フィードバック許容遅延**: **100ms 以下**。これを超えるとプレイヤーは「自分の操作の結果」と知覚しにくくなる
* **身体運動（Exergame / VR）判定バッファ**: **150ms 〜 200ms**。キネステティック・ラグ（身体慣性 300〜800ms）を吸収するための猶予
* **Look-ahead（事前視覚化）**: 判定ライン到達の **2拍前（最小 800ms〜1200ms）** にノーツ／要求動作を明示

**認知負荷上限（CLT の数値指標）**
* **同時アクティブ要素数**: **最大 3〜4 個**（ワーキングメモリの限界 4±1 に準拠、Cowan 2001）
* **モード切替（State Shift）頻度**: **1秒間に1回以上の状態変化要求はパニックを引き起こす**ため排除する。判断の速さではなく、判断の切り替え回数が負荷になる

詳細と設計上の使い方は `core/rhythm-and-synesthesia.md` §2 を参照。

### 2.2 ミニマップとメンタルローテーション
* **アロセントリック（固定北向き）**: プレイヤーが南を向いている時、脳内で180度回転させる補正が必要になる。
* **エゴセントリック（回転追従）**: 補正が不要。
* Shepard & Metzler の法則により、補正コストは角度に比例する。**アクション・リズムなど時間制約の厳しいジャンルでアロセントリックを採用すると、ワーキングメモリを圧迫して操作ミスを誘発する。**
* ただし俯瞰型ストラテジーでは、地図の絶対的な向きが記憶の足場になるため固定のほうが有利な場合がある。**ジャンルで判断が割れる項目**。

### 2.3 メタファー・ボキャブラリー
現実のオブジェクトが、ゲーム内でどこまで現実と同じ振る舞いをするかの度合い。

> 例：ローストターキーが「HP回復アイテムの記号」でしかないのか、「燃やせる・投げられる・匂いで敵を誘導できる物体」なのか。

**ボキャブラリーが広いほど、プレイヤーは説明されていない行動を試すようになる。** 直感性は「正しい操作が分かること」だけでなく、「試したことが通ること」からも生まれる。逆に、記号でしかない物を現実的に描くと偽アフォーダンスになる。

## 3. 操作・タイミングの実務値

**性質**: 以下は業界で広く使われるチューニング値であり、査読研究由来の定数ではない。タイトルごとに調整する前提の出発点として使う。

| 項目 | 目安 |
| :--- | :--- |
| コヨーテタイム（接地を離れた後のジャンプ猶予） | 約 **100ms**（6フレーム@60fps） |
| 入力バッファ（着地前の先行入力受付） | 約 **100〜150ms** |
| ヒットストップ（命中時の停止） | **2〜8フレーム**。重い攻撃ほど長く |
| リズムゲーム PERFECT 判定窓 | **±30〜50ms** |
| リズムゲーム GOOD 判定窓 | **±80〜100ms** |
| 音ズレ検知（音が遅れる方向） | 約 **100ms** から気づかれやすい |
| 音ズレ検知（音が先行する方向） | 約 **45ms** から気づかれやすい（遅れの半分以下） |
| 全身動作の Pre フィードバック | **500ms〜1秒前** |
| 高強度運動の連続上限 | **30〜90秒** |

コヨーテタイムと入力バッファについての実務上の要点：**プレイヤーは自分の入力が遅れたことを自覚していない。** これらが無い状態のテストで返ってくる報告は「操作が難しい」ではなく「**反応しないことがある**」であり、バグとして報告される。

## 4. UI・アクセシビリティの数値

| 項目 | 数値 | 性質 |
| :--- | :--- | :--- |
| タッチターゲット最小 | **44×44pt**（Apple HIG）／ **48×48dp**（Material Design） | 各社の公式ガイドライン |
| 赤緑の識別が困難な割合 | 男性 約**8%** ／ 女性 約**0.5%** | 疫学的推定。**色のみで情報を伝えない**根拠 |
| テキストのコントラスト比 | **4.5:1** 以上（通常）／ **3:1** 以上（大きい文字） | WCAG 2.x AA |
| 光感受性発作のリスク | **3Hz を超える点滅**を画面の広い面積で行わない | 各種放送・ゲーム業界ガイドラインの共通線 |

光感受性は、リズムゲームや共感覚演出で最も見落とされやすい。**周縁（Macro）の派手な演出は、まさにこのリスクの発生源**であるため、点滅頻度と面積の上限を設計時に決めておく。

## 5. アンチパターン集（観測された失敗の型）

| 型 | 症状 | 正体 | 対処 |
| :--- | :--- | :--- | :--- |
| **偽アフォーダンス** | 「バグってる」と報告される | Perceived はあるが Real がない | 機能を付けるか、見た目を変える |
| **反転マッピング** | 説明しても定着しない | 強固な既存スキーマとの衝突 | ルールを変える／両方の設定を用意 |
| **アポフェニア創作** | 存在しないルールでプレイされる | 意味のない差異・空白の放置 | 未使用要素を消すか、意味を与える |
| **記号と物体の混同** | 「なぜこれは燃えないのか」 | メタファー・ボキャブラリーの不統一 | 現実的に描くなら現実的に振る舞わせる |
| **ハロー効果** | アート追加後に「面白くなった」と誤判定 | 見た目が判断を汚染 | グレーボックスで先に検証 |
| **説明で埋める** | チュートリアルが伸び続ける | 設計の欠陥を説明で覆っている | 問い2の1と2に戻る |
| **HUD肥大** | 情報が多くて見ない | 世界側で伝える設計の放棄 | 情報を世界に埋める |
| **判定窓の身体無視** | 「自分が下手なのだと思った」 | 身体の物理遅延を指の基準で測っている | Pre 延長＋判定窓拡大 |
| **UFD** | 壁や机にぶつかる | 無自覚な前進の累積 | 視界内の境界＋交互設計＋自動リセンター |
| **無反応の入力** | 「反応しない」「壊れている」 | Immediate フィードバックの欠落 | 成否と切り離して入力自体に反応を返す |

## 6. 数値の使い方と注意

1. **査読研究と実務値を混ぜて「研究によると」と書かない。** 2章の一部（Cowan、Shepard & Metzler）は査読研究、3章は業界の経験則。混ぜた瞬間に、全体の信頼が実務値のレベルまで落ちる。
2. **1章の実験は、規模が小さく再現の記録も限定的。** 「こういう失敗が起きうる」という設計上の警戒対象としては有効だが、「〇%だから〜すべき」という統計的主張の根拠にはしない。
3. **数値は出発点であって着地点ではない。** コヨーテタイム100msは、あなたのゲームの正解ではなく、テストを始める場所。
4. **対外資料に引用する場合は原典を確認する。** 特に1章の実験は出典表記が本スキル内で完結しておらず、そのままの引用に耐えない。
