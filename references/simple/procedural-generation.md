# 無限ステージ生成と難易度カーブ

終わりのないステージを自動生成する時に読む。実装は `assets/chunk-generator.js`。

**この章の目的はひとつ。「詰み」を絶対に出さないこと。** 現在の速度で物理的に通過不能な配置が1回でも出ると、そのゲームの完全自己責任の原則が崩壊します。しかもランダムに出るのでプレイテストでは見つかりません。

---

## 1. チャンク方式

1マスずつランダムに置くのではなく、**通過可能性が保証された塊（チャンク）**を並べる。

```javascript
{
  id: 'gap_medium',
  minSpeed: 240,       // これ未満の速度では通過不能
  maxSpeed: null,      // 速すぎて通過不能なら上限を設ける
  difficulty: 5,       // 1〜10
  length: 400,
  spawn: (x) => { /* 障害物を配置 */ },
}
```

**なぜチャンクなのか**: 個々の障害物をランダムに置くと、通過可能性の判定が全組み合わせに対して必要になり、現実的に検証できません。チャンク単位なら、**チャンクごとに1回検証すれば済みます**。

### `minSpeed` の決め方

ジャンプの飛距離から逆算します。

```
最大飛距離 = 水平速度 × 滞空時間
滞空時間 ≈ (2 × v_initial) / g   ※非線形重力なら実測が確実
```

**計算値をそのまま使わず、余裕を持たせる**（0.8倍程度）。計算上ギリギリ通過可能な配置は、人間には通過不能です。フレーム単位の正確な入力を要求することになるため。

### 穴の幅は「上下**両方**」で挟む

可変ジャンプ（`mechanics-and-physics.md` §1.1）を入れている場合、速度 `v` に対して跳べる距離は1つではなく**幅を持ちます**。小ジャンプの最大飛距離を `D_min`、長押しの最大飛距離を `D_max` として、穴の幅 `W` は必ずこの間に入れてください。

```
D_min < W < D_max × 0.8
```

- **`W ≥ D_max`** → 物理的に越えられない。詰み
- **`W ≤ D_min`** → **チョン押しでも勝手に越えてしまう**。可変ジャンプが意味を持たず、「押せば何とかなる」区間になる

**下限側の抜けは詰みほど致命的ではないので、見逃されがちです。** ただしこれが多いと、可変ジャンプを入れた意味がプレイヤーに一度も伝わりません。「押した長さで変わる」ことを**教える**のは説明文ではなく、チョン押しでは届かない穴です。生成側の制約が、そのままチュートリアルの代わりになります。

`chunk-generator.js` の `maxSpeed` が、この「速くなった時に除外する」側です。用途は2つあり、どちらも `maxSpeed` で表現します。

| 除外する理由 | 例 |
| :--- | :--- |
| 速すぎて**通過不能**になる | 天井の低いトンネル、短い着地点（跳び越してしまう） |
| 速すぎて**無意味**になる | 低速域向けの小さな穴。高速では押さなくても越えるので、出しても何も起きない |

**`minSpeed` だけ書いて `maxSpeed` を `null` のままにしたチャンクばかりになっていないか確認してください。** そうなっていると、終盤に序盤の易しい配置が混ざり続け、「速いだけで内容が変わらない」という感想になります。

## 2. 重み付け抽出の順序

**順序を守ってください。** 逆にすると、低確率で通過不能なチャンクが混ざる状態になり、そのバグは再現しません。

```
1. 通過可能なものだけにフィルタ   ← 詰み回避の本体。必ず最初
2. 直近N個と同じものを除外        ← 単調さの回避
3. 難易度で重み付けして抽選        ← 難易度カーブ
4. 候補がゼロなら安全な1つに落とす  ← 例外を投げない
```

### 難易度の重み

```
W_i = (D_i)^α        α = 1.5〜2.0
```

**なぜ指数なのか**: 線形（`W = D`）だと、速度が上がっても簡単なチャンクが同じ割合で出続け、体感が単調になります。指数にすると、速度が上がるにつれて難しいものが出る割合が加速します。

| α | 挙動 |
| :--- | :--- |
| 1.0（線形） | いつまでも簡単なのが混ざる。単調 |
| **1.5〜2.0** | 推奨。速度に応じて自然に難しくなる |
| 3.0以上 | 難しいものばかりになり、緩急が消える |

**「緩急」は意図的に残す。** 難しいチャンクが連続すると、集中が切れて離脱します。数チャンクに1回は簡単なものを強制的に挟む（`recent` の管理か、難易度の移動平均で制御）と、休憩が生まれてセッションが伸びます。

## 3. 難易度カーブ

**時間に比例して速くするのは失敗しやすい。** 上手い人ほど早く限界速度に達し、そこで頭打ちになって短時間で飽きます。

```javascript
// 上限に漸近させる
speed = max − (max − base) × 0.5^(elapsed / halfLife)
```

| 方式 | 挙動 |
| :--- | :--- |
| 線形（`base + rate × t`） | いずれ人間の限界を超え、そこで終わる |
| **漸近（推奨）** | 速度は上限に近づき、以降は**配置の難しさ**で難易度が上がる |

漸近型にすると、終盤の難易度は速度ではなくチャンクの選択で決まるようになります。**速度は学習できるが、配置は毎回違う** — この構造が長い伸びしろを作ります。

### プレイヤーの習熟に合わせる（動的難易度）

前回の到達距離を見て `halfLife` を調整する方法もありますが、**慎重に**。プレイヤーが「上手くなった」と感じている時に難易度を上げると、上達の実感を奪います。使うなら、**下げる方向にだけ**（何度も同じ場所で死んでいる人を助ける）が安全です。

## 4. 検証 — リリース前に必ず走らせる

**詰みはランダムに出るので、プレイテストでは見つかりません。** 全速度域を機械的に走査してください。

```javascript
const problems = generator.validate({ from: 0, to: 2000, step: 10 });
if (problems.length) console.warn(problems);
```

`assets/chunk-generator.js` の `validate()` が返すもの:

| 検出 | 意味 |
| :--- | :--- |
| **候補ゼロ** | その速度域で詰む。**リリース不可** |
| **候補が1つだけ** | その速度域で同じ配置しか出ない。単調 |

**シードを固定できるようにしておく**（`rng` を差し替え可能にしてある）。バグ報告を受けた時、同じステージを再現できないと直せません。

## 5. よくある失敗

| 症状 | 原因 | 対処 |
| :--- | :--- | :--- |
| たまに絶対に越えられない配置が出る | 通過可能性のフィルタが抽選の後 | 順序を直す（§2） |
| 同じ配置が連続する | 直近除外がない | `noRepeat` を2以上に |
| 序盤で候補ゼロになり落ちる | 最低速度が全チャンクで高い | フォールバックを用意（実装済み） |
| 中盤から急に理不尽 | α が高すぎる | 1.5〜2.0 に戻す |
| 疲れる、休憩がない | 難しいものが連続 | 緩急を強制的に挟む |
| 上手い人がすぐ飽きる | 線形の速度カーブで頭打ち | 漸近型に変える（§3） |
| バグが再現できない | シード固定していない | `rng` を差し替え可能に（実装済み） |

## 6. チャンクの作り方

最初は **5〜8個**で十分です。多いほど良いわけではありません。

| 難易度 | 個数の目安 | 役割 |
| :--- | :--- | :--- |
| 1〜3（簡単） | 2〜3個 | 休憩。緩急の「緩」 |
| 4〜6（普通） | 2〜3個 | 主戦場 |
| 7〜10（難しい） | 1〜2個 | 山場。出る頻度は低くていい |

**難しいチャンクを増やすより、簡単なチャンクのバリエーションを増やすほうが効きます。** プレイヤーが最も長く見るのはそこだからです。

## 7. 縦に分岐させる（高所ルート）

同じチャンクの中に高さの違う2本の道を通すと、**入力を増やさずに選択が1つ増えます。** 設計の意図は `one-button-runner.md` §6。ここでは生成側の実装だけ。

```javascript
{
  id: 'branch_medium',
  minSpeed: 300,
  maxSpeed: null,
  difficulty: 6,
  length: 600,
  spawn: (x) => {
    spawnGroundLane(x);                    // 安全・障害物多め・報酬少
    spawnUpperLane(x, { y: 220 });         // 狭い足場・報酬多め
    // 上の道から落ちた時に、下の道の「穴の上」に落ちないこと。
    // ここを検証しないと「挑戦した瞬間に理不尽に死ぬ」が起きる
  },
}
```

**検証項目が1つ増えます。** チャンクの通過可能性に加えて、**高所ルートの全区間について、そこから落下した時の着地先が安全であること**を確認してください。上の道を通せるかどうかより、こちらのほうが事故になります。

- 落下先が下の道の穴の上 → 挑戦が即死になり、二度と誰も上に行かなくなる
- 落下先が下の道の障害物の直前 → 反応する猶予がない。着地点の手前 400ms 相当は空けておく

**難易度の付け方**: 分岐チャンクの `difficulty` は**下の道の難しさ**で付けてください。上の道の難しさで付けると、安全な道を選んだだけの人にとって、そのチャンクが不当に高難度として扱われ、難易度カーブが実際より速く上がります。
