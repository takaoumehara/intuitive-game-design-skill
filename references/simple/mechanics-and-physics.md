# 5つのメカニクスの物理実装

選んだ1つのメカニクスを実装する時に読む。実装は `assets/juice-controller.js` にあるので、ここは**なぜその式なのか**と**数値の動かし方**を扱う。

## 目次
1. Tap / Jump — 可変ジャンプと非線形重力
2. Hold & Release — チャージ
3. Pull & Release — 弾性ベクトル
4. Drop & Merge — 落下と合成
5. Timing Stop — 慣性と切断
6. 共通：1ビット入力を豊かにする考え方

---

## 1. Tap / Jump — 可変ジャンプと非線形重力

### 1.1 可変ジャンプ

押した長さで高さが変わる。**1ビットの入力をアナログな表現に変える**、このジャンルで最も重要な仕組み。

垂直速度は、初速に「押している間の上昇力の積分」を足し、重力を引いたもの:

```
vy(t) = v_initial + ∫[0, min(t_hold, t_max)] a_up(τ) dτ − g·t
```

実装上は毎フレーム加算するだけ:

```javascript
if (isHolding && holdTime < maxHoldTime && vy > 0) {
  vy += holdAccel * dt;
  holdTime += dt;
}
```

| 条件 | 挙動 |
| :--- | :--- |
| チョン押し（t_hold → 0） | 上昇力が積まれず、即座に重力が勝って小ジャンプ |
| 長押し（t_max まで） | 上昇力が積まれ続け、最高点に達する |

**`vy > 0` の条件が要点。** これがないと、落下中にボタンを押し直すと空中で再上昇してしまう。

**`maxHoldTime` は 150〜250ms。** これより長いと「押しっぱなし」と区別がつかなくなり、プレイヤーは全部長押しするようになって可変の意味が消えます。

### 1.2 非線形重力

上昇と下降で重力を変えると、**現実にはない気持ちよさ**が出る。

```
a_y = −g₁ − k·vy²        (上昇中：空気抵抗で頂点付近が滞空する)
a_y = −g₂·γ              (下降中：γ = 1.2〜1.8 で素早く落ちる)
```

**なぜこれが効くのか**: 滞空時間が長いと「操作している時間」が増えて気持ちいいが、落下も遅いと着地までが待たされて反応が鈍く感じる。**上を遅く、下を速く**すると、両方が同時に成立する。ほぼ全ての2Dアクションがこれをやっている。

| 数値 | 上げると | 下げると |
| :--- | :--- | :--- |
| `gravityDownScale` (γ) | キビキビ、シビア | ふわふわ、のんびり |
| `dragUp` (k) | 頂点で滞空する、浮遊感 | 素直な放物線 |
| `holdAccel` | 長押しの伸びが大きい | 可変の幅が狭い |

## 2. Hold & Release — チャージ

押している時間を「力」または「角度」に変換し、離した瞬間に解放する。

```javascript
// 溜め: 上限で止めるのではなく往復させると、「ちょうどいい所で離す」
// というタイミングゲームになり、失敗が自分のせいになる
charge += chargeSpeed * dt * direction;
if (charge >= 1 || charge <= 0) direction *= -1;
```

**上限で張り付かせるか、往復させるか**が設計判断。

- **張り付き**: 最大まで溜めるのが常に最適 → 判断がなくなり作業になる
- **往復**: 狙った値で離す必要がある → **判断が生まれる**

往復のほうがゲームになる。ただし往復が速すぎると運になるので、1往復 **1.0〜1.5秒**あたりから調整する。

**溜めている間のフィードバックが命。** 振動・音のピッチ上昇・画面のズーム・キャラの縮み。「今どのくらい溜まっているか」が見えないと、離すタイミングを学習できない。

## 3. Pull & Release — 弾性ベクトル

引っ張った方向と逆に、引いた量に比例した力で飛ぶ（パチンコ）。

```javascript
const dx = startX - currentX;
const dy = startY - currentY;
const dist = Math.min(Math.hypot(dx, dy), MAX_PULL);  // 上限は必ず設ける
const angle = Math.atan2(dy, dx);
velocity.x = Math.cos(angle) * dist * POWER;
velocity.y = Math.sin(angle) * dist * POWER;
```

**軌跡予測線を出すかどうか**が最大の設計判断。

| | 出す | 出さない |
| :--- | :--- | :--- |
| 体験 | 狙う楽しさ、計画的 | 勘と学習、驚き |
| 難易度 | 下がる | 上がる |
| 向いている | パズル寄り（Angry Birds） | アクション寄り |

中間として**予測線を短く出す**（最初の1〜2バウンドまで）方法がある。狙いはつけられるが、その先は分からないので、驚きが残る。

**`MAX_PULL` の上限は必須。** 画面外まで引っ張れると、指の移動距離が体験を支配してしまい、小さい画面の人が不利になる。

## 4. Drop & Merge — 落下と合成

落とす位置だけを決め、あとは物理に任せる。同じものが接触したら次の段階に合成する。

### 4.1 物理の不確定性は「残す」

**このメカニクスの中毒性は、狙った通りに落ちないことから来ている。** 摩擦・反発・回転を適度に効かせ、100%の再現性を持たせない。§2.1 の「ゆらぎ2割」がここに当たる。

ただし**理不尽にはしない**。転がった結果が予測できる範囲に収まっていれば、失敗しても「自分の落とし方が悪かった」と納得できる。反発係数を上げすぎると跳ね回って自己責任感が消える。

### 4.2 合成判定

```javascript
// 接触した瞬間ではなく、両方が「落ち着いている」時に合成する。
// 落下中に合成すると、連鎖が意図せず暴発して何が起きたか分からなくなる。
function shouldMerge(a, b) {
  return a.level === b.level
      && a.level < MAX_LEVEL
      && a.speed < REST_THRESHOLD
      && b.speed < REST_THRESHOLD;
}
```

**合成後の位置は2つの中点、サイズは1段階上。** 合成の瞬間に少し弾ませる（スケールを1.2倍→1.0に戻す）だけで、達成感が大きく変わる。

**連鎖のタメ**: 連鎖が起きる時、各段階の間に **60〜100ms** の間を置く。一瞬で全部処理すると、プレイヤーは何が起きたか認識できず、最大の快感である連鎖が体験されない。

## 5. Timing Stop — 慣性と切断

動いているものを止め、はみ出した分を切り落とす。

```javascript
const overlap = Math.abs(current.x - previous.x);
if (overlap > previous.width) return 'GAME_OVER';
current.width = previous.width - overlap;
current.x = /* 重なった領域の中心 */;
spawnFallingDebris(overlap);   // 切り落とした破片を物理で落とす
```

**破片を落とすことが体験の半分。** 切断が「消える」ではなく「落ちる」と、自分がミスした量が物理量として見える。ニアミス（§2.2）の実装そのもの。

**完全一致（Perfect）への報酬**: ずれが数ピクセル以内なら幅を減らさない、あるいは少し増やす。これがあると、上級者は「幅を減らさずに積み続ける」という別のゲームを遊び始める。**同じ操作のまま深さが増える**（密結合）好例。

**音のピッチを段数で上げる**（`f_n = f_0 × 1.05^n`）。積み上がる感覚が聴覚で分かり、スコア表示より強く効く。実装は `references/audio/`。

## 6. 共通：1ビット入力を豊かにする考え方

メカニクスを増やしたくなったら、その前にこの4つを検討してください。**入力の種類を増やさずに表現を増やす**方法です。

| 手法 | やること | 例 |
| :--- | :--- | :--- |
| **押した長さ** | 時間を量に変える | 可変ジャンプ、チャージ |
| **押したタイミング** | 状況で意味が変わる | 接地中はジャンプ、空中は滑空 |
| **押した回数・間隔** | 連打とリズム | 2回押しで別動作 |
| **押さない選択** | 待つことを判断にする | 通り過ぎるのを待つ |

**「押さない」を設計に入れると、入力ゼロで判断が1つ増えます。** 最も安い深さの作り方です。

これらは全て、本スキル §2 の言う**密結合**（1つの変数に複数の意味を持たせる）の実装形です。新しいボタンを足すのは、これら4つが全て使えなかった時の最後の手段。
