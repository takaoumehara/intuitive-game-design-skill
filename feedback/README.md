# 使用ログから改善する仕組み

このスキルは、使うたびに1件の短い記録を残します。その記録をAIに渡すと、**具体的な修正案と、二度と同じ失敗をしないための回帰テストが返ってきます。**

## なぜこれが必要か

スキルの品質は、出力を眺めても分かりません。出力は「うまくいったように見える」からです。実際に品質を決めているのは、**出力に残らない3つの情報**です。

| 情報 | なぜ重要か |
| :--- | :--- |
| **ユーザーが言い直したこと** | 一度言って伝わらなかったなら、それはスキルに書かれていない指示。**唯一、スキル自身が自分を採点できない指標** |
| **言うべきだったのに言わなかったこと** | 出力に「無い」ものは、読んでも気づけない |
| **読んだが無駄だったファイル** | トークンと時間の浪費。ルーティングの設計ミスの証拠 |

ベンチマークの点数はこの3つを一つも捉えません。実測で96.9%を出した版が、実際には**ユーザーが実行できないコードを出していた**という例が既にあります。

## 使い方

### 1. 記録する（スキルを使ったAIが自動で行う）

作業の終わりに `feedback/log.md` へ7行を追記します。`Corrected:` はユーザーの言葉そのままで書きます（**和らげない**）。

### 2. 渡す

`feedback/log.md` をAIに渡して、こう言うだけです。

> このログを見てスキルを改善して

### 3. AIがやること（この手順に従う）

**ステップ1 — 頻度で仕分ける。** 過剰適合を避けるための線引きです。1件の悪い日と、本物の欠陥を区別します。

| 出現回数 | 対応 |
| :--- | :--- |
| **1回** | 記録に残すだけ。**まだ直さない** |
| **2回** | 調査する。同じ原因か、たまたま似ているだけかを判定 |
| **3回以上** | スキルを直す |

例外：`Wrong:` に**実行不能なコード・存在しないAPI・安全性の問題**が入っていたら、1回でも即座に直します。これらは頻度の問題ではありません。

**ステップ2 — どこが足りないのかを特定する。** 症状ではなく原因の場所を名指します。

| ログの症状 | 疑う場所 |
| :--- | :--- |
| 毎回同じことを指示している | SKILL.md 本文に書かれていない（または奥に埋まっていて読まれていない） |
| 間違った領域のファイルを読んだ | §1 の経路表の記述が曖昧 |
| 読んだが使わなかったファイルがある | 経路の切り分けが甘い。または参照が過剰 |
| コードが動かなかった | §7 の鉄則が守られていない。鉄則自体を強める |
| 出力が長すぎる／回りくどい | テンプレートが重い。削る |

**ステップ3 — 直す。指示を足すのではなく、理由を書く。**

「〜してください」を増やすと、スキルは長くなるだけで従われません。**なぜそれが重要なのかを書くと、書いていない場面にも応用されます。** 迷ったら、直したい振る舞いが起きなかった時に**何が壊れるか**を1文で書いてください。

**ステップ4 — eval ケースに変換する。ここが最も重要です。**

確認された欠陥は、必ず `evals/evals.json` にテストとして追加します。これをやらないと、次の修正で静かに元へ戻ります。

```bash
python3 scripts/log_to_eval.py feedback/log.md
```

ログから eval の雛形を生成します。生成後、アサーションを**観測可能な形**に書き直してください（「良い回答をする」ではなく「〇〇という文字列を含む」「import 文がない」のように）。

**ステップ5 — 記録する。** 直した項目のログエントリに `→ Fixed: <どこをどう直したか>` を追記します。同じ指摘が繰り返されているのに `Fixed` が付いているなら、その修正は効いていません。別の方法を試す合図です。

## やってはいけないこと

- **1件のログでスキルを書き換えない。** 過剰適合します。このスキル自身が「少数の例に最適化するな」と言っているのと同じ理由です
- **`Corrected:` を要約・美化しない。** ユーザーの苛立ちを含んだ言葉そのものが、優先度の情報を持っています
- **eval を追加せずに修正だけする。** 次の修正で戻ります
- **うまくいった回を記録しない。** 失敗だけのログは「壊れている」のか「難しい案件にだけ使われている」のかを区別できません

## ログが溜まったら

10件を超えたら、個別対応ではなく傾向を見ます。

```bash
python3 scripts/log_summary.py feedback/log.md
```

経路別の失敗率、繰り返される `Corrected:`、未修正のまま放置されている項目を集計します。
